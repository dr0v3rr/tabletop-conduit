## Conduit v0.2.11

Manage your poke5e bag from Conduit, tidy up your trainer list, and stay up to date automatically.

### What changed

- **Add items to your poke5e bag.** The Items section now has **＋ Add item** for trainers you own — a searchable picker over the full poke5e item catalogue that creates the row via `add_inventory_item`. This is the only way back once an item has been fully removed, since the ± controls can only change rows that still exist. The Items section (and the button) now stays visible even when the bag is empty, so an emptied bag is no longer a dead end.
- **± quantities actually persist now.** Increasing/decreasing a poke5e item with the ± controls writes back through `update_inventory_item` when you hold the write key. Previously only the catch card's ball-consume persisted; the ± buttons were local-only.
- **Remove vs. Delete a trainer.** Two buttons in the trainer header, matching poke5e's own semantics:
  - **✕ Remove** — forgets the trainer from *your* list only. It stays in poke5e; re-add it any time with its read key. No confirmation (it's reversible).
  - **🗑 Delete** — permanently deletes the trainer from poke5e via `delete_trainer`, behind a confirmation dialog. Only shown for trainers you own (write key).
  - Both are laid out on a dedicated row below the name (Keys on the left, Remove/Delete on the right).
- **Update checker.** Conduit checks the GitHub releases page for a newer version and offers to update; where the platform supports it, it downloads and offers a one-click relaunch.
- **Refresh reloads the poke5e pane.** Reloading now re-loads the poke5e web view too, so the trainer list reflects changes made elsewhere (or a just-deleted trainer).
- **Roster hide/show is a checkbox** (instead of an eye/stop icon), and the window title reads **Conduit v<version>**. Dev builds now show the real Conduit icon and version.

Under the hood: a strict, fail-closed release pipeline (`scripts/release.mjs` + `scripts/verify-release.mjs`) re-hashes every artifact against its update manifest and `SHA256SUMS` before anything is published, so a release can never ship files that don't match their checksums.

No data-format changes. Tests: 263 passing (adds an `add_inventory_item` / catalogue suite and a version-compare suite).
