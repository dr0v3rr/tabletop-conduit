## Conduit v0.2.28

Fixes the poke5e trainer page spinning/crashing after a Pokémon was edited.

### What changed

- **Empty status no longer breaks poke5e.** poke5e's Pokémon status column must be a real status
  (Poisoned, Asleep, …) or empty — but it treats a stored blank (`""`) differently from truly empty,
  and its own trainer/party page crashes on the blank (the page would just spin). `add_pokemon` and
  some existing Pokémon leave that blank behind, and any Conduit write (HP, EXP, status, the added-
  Pokémon type fix) was faithfully carrying it back. Conduit now always clears a blank status to
  "none" on every Pokémon write, so the trainer page loads — and a Pokémon that already had the bad
  value is healed the next time Conduit saves it (e.g. after an HP change or a rest).

This is the real cause of the "trainer page won't load" issue from the last couple of releases. No
settings or data-format changes — existing trainers and Pokémon carry over. Tests: 385 passing.
