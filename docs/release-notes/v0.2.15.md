## Conduit v0.2.15

Conditions now match the sheet you're on — Pokémon get poke5e's own status conditions, and setting one no longer errors.

### What changed

- **Source-specific condition list.** The conditions dropdown now shows the list that fits the loaded
  sheet instead of always showing D&D 5e conditions:
  - **poke5e Pokémon** → poke5e's own statuses (Asleep, Burned, Frozen, Paralysis, Poisoned, Badly
    Poisoned, Confused, Flinched), single-select (poke5e stores one status per Pokémon). Picking one
    writes it back to poke5e (`update_pokemon`'s status field) when you hold the trainer's write key,
    otherwise it's kept locally. The chosen status drives the existing roll effects (burn/poison
    penalties, paralysis saves, ability triggers), which already read the Pokémon's live status.
  - **poke5e trainers & monsters** → the D&D 5e conditions, kept **locally** (there's no backend
    field to write them to). Their roll effects still apply and they're still announced to Roll20.
  - **D&D Beyond characters** → unchanged; conditions still sync to D&D Beyond.
- **Fixes "the parameters provided are invalid" when setting a condition on a poke5e sheet.** Every
  sheet used to route condition toggles to the D&D Beyond condition API, which rejected them for
  non-DDB characters (a trainer/Pokémon has no DDB character id). Conditions are now handled per
  source, so the bad call is gone.
- The Pokémon status is shown and edited in the conditions row now, so it's no longer duplicated in
  the header meta line.

No data-format changes. Tests: 282 passing (adds a poke5e status catalog + status write-back suite).
