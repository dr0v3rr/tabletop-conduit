## Conduit v0.2.7

Native-roll capture fix + a proper app icon.

### What changed

- **Session Log now captures native Roll20 rolls.** The chat scraper only understood *template*
  rolls (`.inlinerollresult` — app cards and the D&D-5e sheet). Manual dice and macro rolls typed
  straight into Roll20 — `/roll`, `/gmroll`, and anything rendered as a `message rollresult` — use a
  completely different DOM (`.formula` / `.rolled` / `.dicegrouping`) with **no** `.inlinerollresult`,
  so they were silently skipped. That's why a campaign showing only its 6 attack rolls was hiding
  saves, damage rolls, GM rolls, and every hand-typed `/roll`. Conduit now parses that native format
  too — player, total, d20-ness, nat-1/nat-20, GM/whisper flag, and dice breakdown — so the log and
  the campaign-wide stats reflect **all** dice, not just sheet-template ones.
  - Verified live against a real campaign: captured rolls went from **6 → 17**, including 4 GM rolls
    (`/gmroll`) and several manual `/roll` results that were previously invisible.
- **Real app icon.** The Windows installer and executables shipped with the generic default icon
  (the reported "Windows *setup* icon"). Conduit now has its own icon — a conduit linking two nodes —
  wired across every platform: the app, the macOS `.icns`, the Linux `.png`, and the Windows `.ico`
  **including the NSIS Setup/uninstaller icons**, so `Conduit Setup.exe` no longer looks generic.

No engine changes, no data-format changes — existing archives and stats carry over. Tests: 226 passing.
