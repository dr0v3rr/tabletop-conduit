## Conduit v0.2.48

### See how every message reached Roll20

A small note at the top right now reports every message Conduit posts to the Roll20 chat: rolls, item
uses, conditions, rests, catches, HP rolls and Display in VTT. Before this, everything but rolls failed
silently.

- **✓ Sent to Roll20**: it arrived as sent.
- **✓ … as a plain card / as text**: the game showed it blank, so it was re-sent in a plainer form.
- **? … hasn't appeared in chat**: it went out, but no new chat message showed up.
- **✕ Not sent**: no Roll20 game is open ("open a Roll20 game first" instead of a technical error).

### No more blank cards

- **Using a no-dice item** (a poke5e Potion, say) posted a title-only card that some games show empty.
  The card now also lists how many are left.
- **Every card is checked after posting**, not just D&D-sheet rolls. If it comes out blank, it is
  re-sent on Roll20's built-in card, then as plain chat text, which always shows. Dice still roll. A card
  that showed is never posted twice.
- **Display in VTT** goes through the same check.

### Display in VTT keeps PP private

A displayed move no longer shows its PP. A GM showing an enemy's move would otherwise reveal how many
uses it has left. Your own sheet still shows PP.

### Security

- Build tooling: `minimatch` raised to 11.0.5 (GHSA-g3hv-75wg-m249). The affected copies are only used
  by the build tool and were never in the app. `npm audit`: 0 vulnerabilities.

Tests: 476 passing.
